### Phase 1+2+Statistics — IV&V parallel  (≈20–30 min, codex × 3 in parallel)

Three independent codex tasks run in parallel; **none receives the others'
output** (IV&V principle). Single message dispatching three Agent / codex
exec calls.

**Phase 1 (Blueteam)** — argument map. Inputs: ch1+ch3+ch4+ch5 +
abstract + chapter guides. Output:
`paper/dissertation/review/2026-05-02/phase1_blueteam.md`
- core-claim → evidence (Ch:Sec:Line) mapping for the 3 main contributions
- 5 failure scenarios + mitigations
- per-chapter weakest paragraph

**Phase 2 (Redteam)** — adversarial attacks. Inputs: ch1+ch3+ch4+ch5 +
abstract + `05_error_taxonomy.md`. **No blueteam output.** Output:
`paper/dissertation/review/2026-05-02/phase2_redteam.md`
- Critical / Major / Minor classification
- explicit attack on Wave 5 Branch C interpretation, panel-size limit
  framing, and Layer A vs Layer A' provenance argument

**Statistics** — formal statistical review. Inputs: ch3_methods + ch4_results
+ verify_dissertation.py output + Wave 1+5 supporting reports + memory's
`fairness_issue.md`. Output:
`paper/dissertation/review/2026-05-02/phase2_statistics.md`
- 10-item PASS/WARN/FAIL: ω² interpretation, paired vs unpaired tests,
  multiple comparisons, sign-stability bootstrap, MCC vs precision@20
  ceiling, sample-size justification, Wave 5 Welch t cross-panel comparison
  caveat enforcement, etc.
- **Step 10 (mandatory, codex-recommended)**: explicit fairness check —
  is the Layer A vs `freq` correlation issue from
  `~/.claude/projects/-proj-paper/memory/fairness_issue.md` actively
  framed as correlation/circularity risk in the manuscript, or buried in
  generic limitations? Output PASS/WARN/FAIL + suggested prose location.
- core-claim statistical reliability rating

**Codex routing note**: any prompt that names "escape", "neutralization
escape", or "antibody footprint" risks the OpenAI biosafety filter (we hit
this twice on 2026-05-02). Use neutral terminology — "annotated functional
residues", "literature-curated label set", "structured public-database
features" — and reference the existing review reports rather than
re-quoting biological detail.

### Phase 3 — CCB arbitration + seeded reconciliation  (≈25 min, codex)

Inputs: phase1 + phase2 + statistics outputs + ch1+ch3+ch4+ch5 + abstract.
Single codex task.

For each attack: classify as (a) already addressed, (b) requires
manuscript fix, (c) attack is invalid. Output:
`paper/dissertation/review/2026-05-02/phase3_ccb.md`
- explicit verdict per attack
- severity disputes flagged for user
- **Andon code**: any unresolved Critical attack blocks Phase 4.
- **Seeded reconciliation step (codex-recommended)**: after IV&V verdicts,
  run a second pass that asks (i) does any Redteam/Statistics finding
  invalidate a Blueteam claim-evidence map, and (ii) does Blueteam expose
  a missing statistical check the Statistics phase should have made?
  Preserves IV&V independence in the first pass while gaining the benefit
  of sequential synthesis afterwards.
- **Fairness escalation (codex-recommended)**: if Statistics step 10
  flags the `fairness_issue.md` concern as inadequately framed, CCB
  decides whether prose fix is required vs. acceptable as currently
  worded.

**Deadlock policy**: if Phase 3 escalates to cycle 2 with the same Critical
unresolved, user decides between:
1. Weaken the claim in prose to resolve, or
2. Run a new analysis to satisfy.

### Phase 4 — Professor simulation  (≈25 min, codex)

Inputs: ch1+ch3+ch4+ch5 + abstract + Phase 1/2/3 summary digest.
Output: `paper/dissertation/review/2026-05-02/phase4_professor.md`

**Pass criterion (revised per codex review — single calibrated gate):**
memory-defined `professor_evaluation_skill.md` 10-professor 9-item rubric.
Pass requires:
- total ≥ 80/100 (A− grade)
- no single rubric item < 6
- no unresolved Critical from Phase 3.

The skill-defined "mean ≥ 7, individual minimum ≥ 5" output is computed
and reported as a **diagnostic appendix** but is no longer a gate. The
memory rubric is closer to the actual defense simulation, names the
10-professor structure explicitly, and is stricter where it matters
(min ≥ 6 vs. min ≥ 5).

If gate fails: list the failing rubric item(s) and propose targeted
prose fixes, then re-run Phase 4 only.

### Final — Summary  (≈10 min, claude)

Aggregate to
`paper/dissertation/review/2026-05-02/summary.md` per the skill's required
format. Commit as a "docs: dissertation audit cycle 1" commit (no prose
changes if all gates pass).

If any gate fails or any Critical persists, do **not** commit a clean
verdict — report status to user and stop.
