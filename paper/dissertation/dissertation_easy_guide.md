# MutBench 학위논문 쉬운 설명서

**한줄 요약**: 바이러스 변이 핫스팟을 찾는 방법이 여러 개 있는데, 어떤 방법이 좋은지 비교할 기준이 없었다. 이 논문이 그 기준(MutBench)을 만들고, "모든 바이러스에 통하는 만능 방법은 없다"는 것을 통계적으로 증명했다.

---

## 1. 배경: 바이러스 변이란?

바이러스는 복제할 때 유전자(A, C, G, U 서열)를 복사하는데, 이때 오류가 생긴다. 이 오류가 **변이(mutation)**다. SARS-CoV-2는 약 30,000개 염기로 이루어져 있고, 코로나 유행 중 수많은 변이가 쌓였다.

**핫스팟(hotspot)**이란 변이가 유독 많이 생기는 위치를 말한다. 단순히 많이 생기는 것이 아니라, 바이러스가 인간 면역을 회피하거나 감염력을 높이기 위해 "선택적으로" 변이하는 곳이다.

핫스팟을 정확히 찾으면:
- **백신 설계**: 핫스팟을 피한 안정적인 부위를 타겟
- **항바이러스제**: 핫스팟 회피 변이를 예측
- **감시 체계**: 위험 변이주 조기 경보

---

## 2. 문제: 기준이 없다

핫스팟을 찾는 방법(알고리즘)이 여러 개 있다:
- **빈도 기반**: 변이가 많은 곳 = 핫스팟
- **엔트로피 기반**: 변이 종류가 다양한 곳 = 핫스팟
- **클러스터링**: 변이가 뭉쳐 있는 곳 = 핫스팟
- **통계 검정**: 배경 대비 유의하게 높은 곳 = 핫스팟

**문제는**: 이 방법들 중 어느 것이 더 좋은지 비교할 수 없었다.

왜?
1. **정답이 없다** — "여기가 진짜 핫스팟이다"라는 공인된 정답표가 없음
2. **각자 다른 데이터로 평가** — 방법 A는 코로나로, 방법 B는 인플루엔자로 테스트하니 비교 불가
3. **하나의 바이러스만 테스트** — 코로나에서 좋은 방법이 HIV에서도 좋을지 아무도 모름

비유하면: 학생들의 시험 성적을 비교하고 싶은데, 모두 다른 과목의 다른 시험을 봤고, 채점 기준도 다른 상황.

---

## 3. 해결: MutBench

이 논문이 만든 MutBench는 **공정한 시험지 + 채점 기준 + 다양한 과목**을 제공한다.

### 3.1 정답표: 3층 Ground Truth

"진짜 핫스팟"을 정의하기 위해 3가지 독립적인 생물학적 근거를 결합했다:

| 층 | 의미 | 역할 | 쉬운 설명 |
|----|------|------|----------|
| **Layer A** | 수렴 진화 위치 | 정답(양성) | 서로 다른 바이러스 계통에서 독립적으로 같은 변이가 반복 발생 → "진짜 중요한 곳" |
| **Layer B** | 보존 구조 영역 | 오답(음성) | 변이가 생기면 바이러스가 죽는 곳 → "여기를 핫스팟이라고 하면 틀림" |
| **Layer C** | DMS 실험 데이터 | 검증 | 실험실에서 모든 가능한 변이를 만들어 기능 영향을 측정한 데이터 |

세 근거는 거의 겹치지 않는다 (Jaccard 유사도 0.006). 즉 각각 다른 관점에서 독립적으로 정답을 제공한다.

### 3.2 채점 기준: Hotspot-score

탐지 방법의 성능을 **하나의 점수**로 평가:

```
hotspot-score = (recall + precision + stability) / 3
```

- **Recall (재현율)**: 진짜 핫스팟 중 얼마나 찾았는가? (놓친 것은 없는가?)
- **Precision (정밀도)**: 찾은 것 중 진짜가 얼마인가? (헛것을 찾진 않았는가?)
- **Stability (안정성)**: 데이터를 조금 바꿔도 같은 결과가 나오는가? (재현 가능한가?)

세 가지를 동시에 보는 이유: recall만 높으면 게놈 전체를 핫스팟이라고 하면 되고, precision만 높으면 가장 확실한 1개만 보고하면 된다. 둘 다 의미 없다.

### 3.3 시험 범위: 9개 바이러스

코로나(SARS-CoV-2)뿐 아니라 인플루엔자(H3N2, B형), 노로바이러스, HIV-1, 뎅기, RSV, MERS, C형간염(HCV)까지 **9개 RNA 바이러스**를 대상으로 했다.

각 바이러스에 대해 **9가지 점수화 방법 × 41가지 탐지 알고리즘 = 369가지 조합**을 평가했다.
총 **3,321회** 평가. (일부 조합은 아무것도 탐지하지 못해 유효 평가는 2,544회)

## 4. 실험: 2단계 설계

### Stage 1: SARS-CoV-2 심층 분석

먼저 코로나 하나에 집중해서 프레임워크가 잘 작동하는지 검증:

- **합성 데이터 테스트**: 정답을 미리 심어놓고 얼마나 잘 찾는지 확인
  - MutClust-Hybrid가 최고 성능 (hotspot-score 0.778)
- **실제 데이터 테스트**: GISAID의 실제 코로나 서열 사용
  - 합성 대비 성능 하락 (F1: 0.785 → 0.123), 하지만 정답 근처에서 6.9배 이상 enrichment
- **시간 안정성**: 2020년 데이터로 훈련 → 2024년 데이터에서 테스트
- **민감도 분석**: 파라미터를 바꿔도 결과가 안정적인지

### Stage 2: 9개 바이러스 대규모 비교

핵심 질문: **코로나에서 제일 좋은 방법이 다른 바이러스에서도 제일 좋은가?**

답: **아니다.**

## 5. 핵심 결과: "만능 방법은 없다"

4가지 독립적 통계 증거가 같은 결론을 가리킨다:

### 증거 1: ANOVA — 상호작용이 가장 크다

"어떤 방법이 좋은가"는 **방법 자체보다 "방법 × 바이러스 조합"에 더 많이 달려 있다.**

| 요인 | 성능 분산 설명 비율 |
|------|---------------------|
| **탐지 방법 × 바이러스 상호작용** | **28.5%** (가장 큼) |
| 바이러스 자체 | 26.0% |
| 점수화 × 바이러스 | 8.3% |
| 점수화 방법 자체 | 2.7% |
| 탐지 방법 자체 | 2.5% |

쉽게 말하면: "이 방법이 좋다/나쁘다"가 아니라 "이 방법이 **이 바이러스에서는** 좋다/나쁘다"인 것이다.

### 증거 2: 9/9 고유 최적 조합

9개 바이러스 모두 서로 다른 최적 조합을 가진다. 단 하나의 조합도 2개 이상의 바이러스에서 동시에 최적이 아니다.

| 바이러스 | 최적 점수화 | 최적 탐지 |
|---------|-----------|---------|
| SARS-CoV-2 | E×rare | CUSUM |
| H3N2 | E_only | SlidingTest |
| Norovirus | P×E×rare | Wavelet |
| HIV-1 | E×rare | FreqThresh |
| ... | ... (모두 다름) | ... |

### 증거 3: Friedman 검정

"상위 20개 조합의 성능 순위가 바이러스마다 바뀌는가?" → **예** (p = 0.0015)

통계적으로 유의하게 순위가 바뀐다. 즉 "보편적 상위권 방법"이 존재하지 않는다.

### 증거 4: LOPO 교차 검증

**Leave-One-Pathogen-Out**: 8개 바이러스에서 최적인 조합을 찾아 나머지 1개에 적용

결과: **0/9 일치**

9번 시도에서 단 한 번도 맞지 않았다. 다른 바이러스에서 좋은 방법이 이 바이러스에서도 좋을 것이라는 기대는 완전히 빗나간다.

## 6. 추가 검증

### ESM-2: 딥러닝도 같은 패턴

단백질 언어 모델(ESM-2, 6.5억 파라미터)로 완전히 다른 방식의 점수를 만들어도:
- SARS-CoV-2와 MERS에서는 **1위**
- 노로바이러스와 HIV에서는 **꼴찌(10위)**

딥러닝조차 바이러스 의존성을 벗어나지 못한다.

### 계통발생 보정: H-score의 근본 한계

H-score(변이 빈도 기반 점수)는 **founder effect**(특정 변이가 많은 이유가 "유리해서"가 아니라 "그 계통이 우연히 번성해서")를 구분하지 못한다.

실험 결과: H-score와 실제 독립적 변이 횟수의 상관관계는 **ρ = -0.876** (강한 음의 상관). 즉 H-score가 높은 곳이 오히려 독립적 변이가 적다.

## 7. PAHD: 바이러스 맞춤형 방법 선택

"만능 방법이 없다"면 → **바이러스에 맞는 방법을 골라야 한다.**

**PAHD (Pathogen-Adaptive Hotspot Detection)**: 바이러스의 게놈 특성(길이, 다양성, GT 밀도 등)을 프로파일로 만들어, 유사한 바이러스에서 잘 작동한 방법을 추천하는 시스템.

현재는 **개념 증명(proof-of-concept)** 단계:
- 대략적 수준(탐지 패밀리 단위)에서 oracle 성능의 48~58% 회복
- 정확한 조합 예측은 0/9 (데이터 9개로는 부족)
- 20개 이상의 바이러스 데이터가 확보되면 실용적 수준에 도달할 것으로 예상

---

## 8. 한계

- **Ground truth가 완벽하지 않다**: 3층 GT 중 DMS 데이터는 9개 중 4개 바이러스에만 존재
- **RNA 바이러스만 테스트**: DNA 바이러스(HPV, HBV 등)는 변이 속도가 달라 별도 검증 필요
- **계통발생 보정 미완**: founder effect 문제를 인지하고 검증했지만, 파이프라인에 완전 통합은 향후 과제
- **PAHD 데이터 부족**: 9개 바이러스로는 방법 예측이 신뢰할 수 없음

## 10. 한줄 결론

> 바이러스마다 최적의 핫스팟 탐지 방법이 다르다. 따라서 하나의 방법을 모든 바이러스에 적용하는 현재 관행은 체계적으로 성능이 떨어진다. MutBench가 이를 증명했고, 앞으로는 바이러스 특성에 맞는 방법을 선택해야 한다.
